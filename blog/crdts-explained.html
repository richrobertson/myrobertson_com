CRDTs Explained

CRDTs are data structures designed so concurrent updates merge deterministically without coordination.

Definition

CRDTs are data structures designed so concurrent updates merge deterministically without coordination.

Key Concepts

  • Commutative/associative/idempotent merge rules.
  • State-based and operation-based CRDT variants.
  • Eliminates many write-write conflict classes.
  • Trades storage/metadata for merge safety.

How It Works

Replicas apply local updates and exchange either full state or operations; merge logic guarantees convergence regardless of message order.

Production Implications

CRDTs reduce human conflict resolution burden in distributed collaboration systems. Even teams on Dynamo/Cassandra stacks sometimes adopt CRDT-like app-level structures for counters, sets, and presence state.

When to Use / Not Use

Use It When

  • Counters, sets, presence, and collaboration artifacts.
  • Offline-first synchronization flows.

Avoid It When

  • Domains requiring strict global invariants and serializable transactions.
  • Extremely constrained payload footprints where metadata is too costly.

Key Takeaways

  • Start with user-visible correctness requirements, then choose the weakest model that still preserves them.
  • Instrument staleness and conflict rates; treat them as first-class production metrics.
  • Design reconciliation and repair workflows before incidents force ad-hoc fixes.
